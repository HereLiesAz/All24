# Firestore Data Schema

The application's backend persistence layer is Google Firestore. The database is structured around
four root collections.

## 1. Collection: `places`

* **Purpose:** This collection stores the canonical records for all approved, publicly visible
  locations in the app. Documents in this collection are the "destinations" that can be recommended
  to users.
* **Data Model:** `com.hereliesaz.all24.data.Place`

| Field         | Data Type              | Nullable | Description                                                                                                     |
|:--------------|:-----------------------|:---------|:----------------------------------------------------------------------------------------------------------------|
| `id`          | `String` (@DocumentId) | No       | The unique document ID generated by Firestore. Serves as the primary key.                                       |
| `name`        | `String`               | No       | The public name of the establishment.                                                                           |
| `description` | `String`               | No       | A curated description of the place. This is intended to be evocative rather than purely informational.          |
| `location`    | `GeoPoint`             | Yes      | The physical coordinates of the establishment. Intended for admin reference only.                               |
| `category`    | `String`               | No       | A simple classification string (e.g., "bar", "popUp").                                                          |
| `ownerId`     | `String`               | Yes      | The `uid` of the user who owns this place. Acts as a foreign key to the `users` collection.                     |
| `tags`        | `List<String>`         | No       | A list of strings used to assign this place to one or more UI categories (e.g., "Happy Hours", "24-Hour Bars"). |

## 2. Collection: `reviews`

* **Purpose:** This collection aggregates all user- and admin-generated reviews for the locations in
  the `places` collection. It is the primary mechanism for user-generated content and opinion.
* **Data Model:** `com.hereliesaz.all24.data.Review`

| Field           | Data Type                      | Nullable | Description                                                                                                                                                                         |
|:----------------|:-------------------------------|:---------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `id`            | `String` (@DocumentId)         | No       | The unique document ID for the review.                                                                                                                                              |
| `placeId`       | `String`                       | No       | A foreign key linking to a document in the `places` collection.                                                                                                                     |
| `userId`        | `String`                       | No       | The `uid` of the user who created the review.                                                                                                                                       |
| `text`          | `String`                       | No       | The textual content of the review.                                                                                                                                                  |
| `vote`          | `String`                       | No       | A required binary choice: must be either `"endorse"` or `"avoid"`. The system intentionally disallows nuanced or star-based ratings to enforce a strong opinion.                    |
| `timestamp`     | `Timestamp` (@ServerTimestamp) | Yes      | A server-generated timestamp indicating when the review was created. It's nullable in the model to accommodate latency before the server value is set.                              |
| `endorsedBy`    | `List<String>`                 | No       | A list of `uid`s from users who have endorsed this review. This is managed via `FieldValue.arrayUnion` and `arrayRemove` operations.                                                |
| `avoidedBy`     | `List<String>`                 | No       | A list of `uid`s from users who have disputed this review.                                                                                                                          |
| `isAdminReview` | `Boolean`                      | No       | A flag indicating if the review was created by an admin. If `true`, the UI must give this review visual priority and sort it to the top of its respective `PlaceDetailScreen` list. |

## 3. Collection: `users`

* **Purpose:** This collection stores data for registered (non-anonymous) users, mapping their
  Firebase Authentication `uid` to application-specific data like their role.
* **Data Model:** `com.hereliesaz.all24.data.UserModel`

| Field   | Data Type              | Nullable | Description                                                                                                                              |
|:--------|:-----------------------|:---------|:-----------------------------------------------------------------------------------------------------------------------------------------|
| `uid`   | `String` (@DocumentId) | No       | The user's `uid` from Firebase Authentication, which serves as the primary key for this collection.                                      |
| `email` | `String`               | No       | The email address the user registered with.                                                                                              |
| `role`  | `String`               | No       | The user's role, determining their permissions. Must be one of `"user"`, `"business"`, or `"admin"`. Defaults to `"user"` upon creation. |

## 4. Collection: `place_submissions`

* **Purpose:** This collection serves as a temporary holding area or "purgatory" for new place
  submissions from users. Documents here are not publicly visible and exist only to be reviewed by
  an admin.
* **Data Model:** `com.hereliesaz.all24.data.Submission`

| Field         | Data Type                      | Nullable | Description                                                                                                                                                   |
|:--------------|:-------------------------------|:---------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `id`          | `String` (@DocumentId)         | No       | The unique document ID for the submission.                                                                                                                    |
| `name`        | `String`                       | No       | The proposed name of the new place.                                                                                                                           |
| `description` | `String`                       | No       | The user's submitted description for the place.                                                                                                               |
| `address`     | `String`                       | No       | The submitted physical address. This is a simple string that the admin must manually parse or verify; there is no automatic geocoding at submission time.     |
| `category`    | `String`                       | No       | The user's suggested category for the place.                                                                                                                  |
| `submittedBy` | `String`                       | No       | The `uid` of the user who submitted the request.                                                                                                              |
| `submittedAt` | `Timestamp` (@ServerTimestamp) | Yes      | A server-generated timestamp of when the submission was created.                                                                                              |
| `status`      | `String`                       | No       | The current state of the submission. This is always `"pending"` by default. Upon admin action, the document is deleted rather than having its status updated. |
